# Аудит фронтенда Чешуи

Дата: 15 октября 2026. Исходная версия: `3f0a91e1d9adb3a0cae04dd4099172fdfa8c6fc9`.

## Область проверки

Публичный сайт публикуется из `dist` через GitHub Pages. Next.js и статические HTML — два отдельных представления сайта. Поэтому проверены опубликованные HTML/JS и сборка/галереи Next.js. Репозиторий не клонировался на компьютер пользователя: сборка, браузеры и обработка изображений работают на GitHub Actions.

## Найдено и исправлено

| Проблема | Исправление |
| --- | --- |
| Главная загружала старые фотографии и подменяла их новыми после DOMContentLoaded | Итоговые фотографии, ссылки и карточки находятся непосредственно в HTML |
| Фотографии ниже первого экрана конкурировали с основной фотографией | Сначала загружается основная фотография; затем включается нативная ленивая загрузка остальных. Прокрутка или взаимодействие включают их сразу, есть резервный таймер и noscript |
| Везде задавалось одно значение sizes, даже для узких карточек | sizes соответствует карточке, каталогу, главной фотографии или галерее; fallback — существующий WebP вместо многомегабайтных PNG |
| Между 600 и 1200 px не было подходящего размера для телефона | Добавлены производные варианты 400 и 800 px; они генерируются автоматически до сборки и публикации |
| Превью 54–62 px запрашивали фотографии шириной 600 px | Производные превью 192 px генерируются из существующих WebP при проверке и публикации |
| Скрипты в head блокировали разбор HTML; главная содержала цепочку патчей после закрытия документа | Скрипты с defer, единая разметка и один обработчик для каждого действия |
| Переключение языка падало из-за удалённого элемента и неверно переименовывало пункты меню | Переводы привязаны к существующим элементам и постоянным идентификаторам |
| Кнопка меню зина также перенаправляла на главную | Удалён конкурирующий обработчик |
| Закрытие внутреннего меню вызывало after is not a function | Единое меню, корректные обработчики, Escape, блокировка фона, удержание и возврат фокуса |
| В подвале были элементы a без href, часть карточек не работала с клавиатуры | Настоящие ссылки вместо имитации кликов |
| Каталог объектов показывал старые фотографии | Те же три актуальных объекта, что на главной, и общий просмотр фотографий |
| Страница выставки без корректного id оставалась пустой | Переход в каталог выставок |
| Прокручиваемые галереи не получали фокус | Фокус, подписи и управление стрелками клавиатуры |
| На коротком экране фиксированная высота могла скрыть описание | Страница может прокручиваться по вертикали; размер сцены стабилен при смене фотографий |
| Часть художественных работ в каталоге обрезалась | contain в каталогах рисунков и объектов |
| Название диалога меню отсутствовало в React | Добавлен доступный заголовок Sheet |
| Декоративные анимации продолжались при reduced motion | Общее отключение переходов, анимаций и плавной автопрокрутки |

Новые зависимости приложения не добавлялись. Sharp уже присутствовал в devDependencies; Playwright и axe-core устанавливаются только во временный каталог CI. Оригиналы изображений не удалялись и не перекодировались.

## Проверки

- `npm run build`: компиляция, TypeScript, статический экспорт.
- Существующие проверки двух главных и 15 галерей: быстрые и обратные нажатия, resize, свайпы, reduced motion, геометрия карточек и стрелок.
- 17 статических маршрутов: главная, четыре каталога, три зина, цианотипии, восемь выставок.
- Разрешения 320, 390, 768, 1440 px; проверка горизонтального переполнения.
- Доступность через axe-core (WCAG A/AA), работа меню, языка, ссылок, вкладок, просмотра объектов, возврата по якорю.
- Доступность всех найденных вариантов изображений и внутренних ссылок, ошибки браузера и HTTP.
- Снимки главной на мобильном и широком экране.

## Как читать замеры

`scripts/audit-site.mjs` сравнивает исходный commit и исправленную версию на одном GitHub runner: Chromium, 390×844, DPR 2, холодный контекст, сеть 1.6 Мбит/с, задержка 150 мс, CPU ×4. LCP измеряется после появления основной фотографии; её загрузка не подменяется ранним текстовым LCP.

Это лабораторное сравнение, а не статистика реальных посетителей и не оценка Lighthouse. Размер переданных ресурсов относится к зафиксированному моменту первого экрана, а не ко всему архиву. Скорость внешнего CDN и соединение посетителя могут изменить время. Результаты, waterfall запросов и снимки находятся в артефакте `frontend-audit` соответствующего GitHub Actions запуска.

## Что улучшать следующим этапом

1. **Единый источник сайта и контента.** Сейчас Pages публикует `dist`, а Next.js строится отдельно. Самая полезная архитектурная доработка — выпускать одну версию из одного набора данных, чтобы фотографии и функции не расходились. Полная миграция движка требует отдельного решения и не включена в исправление производительности.
2. **AVIF при необходимости.** Если реальные замеры подтвердят, что фотографии остаются узким местом после добавления 400/800 px, рассмотреть AVIF через picture с WebP fallback и генерацией из оригиналов. Сравнивать качество и вес на конкретных работах.
3. **Наблюдать реальные Core Web Vitals.** Проверять LCP, INP, CLS на реальных устройствах и при доступности данных CrUX. CI оставить как защиту от регрессий; один лабораторный запуск не гарантирует скорость у всех посетителей.
4. **Настройки CDN — при смене хостинга.** Для версионированных ассетов полезно длительное кеширование; HTML должен обновляться отдельно. GitHub Pages не даёт произвольно выставлять собственные Cache-Control, поэтому не добавлялся фиктивный файл заголовков.

Основания для приоритетов: [оптимизация LCP](https://web.dev/articles/optimize-lcp), [ленивая загрузка изображений](https://web.dev/articles/browser-level-image-lazy-loading), [defer для script](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script).
